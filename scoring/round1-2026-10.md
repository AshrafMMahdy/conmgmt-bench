## How each number was made (open scoring, reproducible)

1. **Expectations** — the bench's own 0 / 0.5 / 1 per rule, with a one-line reason each (in `scenarios/<id>/scores/<run>.json`).
2. **Key** — for S4 (sealed answer key with four heads): found 1 / partial 0.5 / missed 0, averaged with the expectations mean. 21's key is already covered by its expectations; PRE-01 has no key.
3. **Journey deductions** (the part a binary scorer cannot see): follow-up needed to finish −0.10 each; plan not kept current to the end −0.05; shipped without reviewer approval −0.10 (no revision attempt) or −0.05 (revised but still unapproved); a delivered file with a real defect (inconsistent dates, cosmetic breaks, analyses run before the last edit) −0.05.
4. **Relative score** = final ÷ the published baseline-1.0 outcome for that scenario (expectations mean, averaged with the key score where a key exists). The baseline is a reference, not a ceiling: scores above 1.00 are expected.

Baselines: PRE-01 = DeepSeek V4 Pro, chained, 0.92. S4 = MiniMax M3, chained, 0.88 + key 4/4 → 0.94. 21 = GLM 5.3 Flash, the 2026-10-03 development chat on an earlier brief (no discharge time, no markup), scored on the four expectations it was asked → 0.875.
